# نظام كاشير حلواني السفير (Elsafeer POS)

نظام كاشير (Point of Sale) بسيط وسريع لمحلات الحلويات، متعدد الفروع، مبني بـ
**React + Node.js/Express + MongoDB**.

هذا نظام كاشير فقط — **بدون** إدارة مخزون أو محاسبة متقدمة أو نظام ERP.

---

## 1. البنية التقنية

```
elsafeer-pos/
├── backend/     Node.js + Express + MongoDB (Mongoose) + JWT
└── frontend/    React + Vite + React Router + Axios (واجهة عربية RTL)
```

### الموديلات (Collections) في قاعدة البيانات
```
users        - المستخدمون (مالك / كاشير) + الفرع المرتبط بهم
branches     - الفروع (الإسماعيلية، فايد، سرابيوم)
categories   - الأصناف (شرقي، غربي، منتجات العيد، حلاوة المولد، رمضان)
products     - المنتجات (اسم، سعر، وحدة: قطعة أو كيلو)
shifts       - الشيفتات (صباحي/مسائي) بحالة مفتوح/مغلق وملخص مالي عند الإغلاق
sales        - المبيعات، وتحتوي على مصفوفة المنتجات المباعة مباشرة (لا يوجد موديل items منفصل)
```

---

## 2. المتطلبات الأساسية

- Node.js 18+ و npm
- MongoDB يعمل محليًا أو عنوان اتصال MongoDB Atlas

### تثبيت MongoDB محليًا (اختصارًا)
- macOS: `brew tap mongodb/brew && brew install mongodb-community && brew services start mongodb-community`
- Ubuntu/Debian: اتبع تعليمات [التثبيت الرسمية](https://www.mongodb.com/docs/manual/administration/install-on-linux/)
- Windows: حمّل [MongoDB Community Server](https://www.mongodb.com/try/download/community)
- أو استخدم [MongoDB Atlas](https://www.mongodb.com/atlas) (سحابي مجاني) واستخدم رابط الاتصال (connection string) كقيمة `MONGO_URI`

تأكد أن MongoDB يعمل على `mongodb://127.0.0.1:27017` (أو استخدم رابطك الخاص).

## 3. تشغيل الـ Backend

```bash
cd backend
cp .env.example .env
# عدّل .env إذا لزم الأمر (خصوصًا MONGO_URI و JWT_SECRET)

npm install

# تعبئة قاعدة البيانات ببيانات تجريبية (فروع، أصناف، منتجات، مستخدمين)
npm run seed

# تشغيل السيرفر (وضع تطوير مع إعادة تحميل تلقائي)
npm run dev
# أو تشغيل عادي
npm start
```

السيرفر سيعمل افتراضيًا على: `http://localhost:5000`
يمكنك التأكد من عمله عبر: `http://localhost:5000/api/health`

### حسابات تجريبية بعد تشغيل `npm run seed`

| الدور   | اسم المستخدم | كلمة المرور  | الفرع        |
|---------|--------------|--------------|--------------|
| مالك    | `owner`      | `owner123`   | كل الفروع    |
| كاشير   | `ismailia1`  | `cashier123` | الإسماعيلية  |
| كاشير   | `fayed1`     | `cashier123` | فايد         |
| كاشير   | `sarabium1`  | `cashier123` | سرابيوم      |

## 4. تشغيل الـ Frontend

في نافذة طرفية (terminal) أخرى:

```bash
cd frontend
```

الواجهة ستعمل افتراضيًا على: `http://localhost:5173`

## 5. تسلسل الاستخدام (Flow) الكامل

1. **تسجيل الدخول** بحساب كاشير (مثلاً `ismailia1` / `cashier123`).
2. النظام يوجهك تلقائيًا لفرعك (بدون اختيار يدوي).
3. من لوحة التحكم: **فتح الكاشير** → إذا لم يوجد شيفت مفتوح، يطلب منك **فتح شيفت** (صباحي/مسائي).
4. في شاشة الكاشير (POS):
   - اختر **الصنف** من القائمة اليمنى.
   - اضغط على **المنتج** لإضافته للسلة (يحدد النظام تلقائيًا هل تُدخل قطعة أو وزن حسب المنتج).
   - عدّل الكمية/الوزن أو احذف منتجًا من السلة.
   - أدخل **رقم هاتف العميل** (اختياري).
   - أدخل **الخصم** إن وجد.
   - اختر **طريقة الدفع**: نقدي / فيزا / محفظة.
   - إذا اخترت **نقدي**: أدخل المبلغ المدفوع، ويُحسب الباقي تلقائيًا (لا يمكن التأكيد إذا كان المبلغ أقل من الإجمالي).
   - اضغط **تأكيد البيع**.
5. تظهر **الفاتورة** تلقائيًا مع زر **طباعة الفاتورة**.
6. يمكنك مراجعة العملية في **سجل المبيعات** (مع فلاتر التاريخ/طريقة الدفع/الشيفت).
7. راجع **التقارير** لملخص المبيعات خلال فترة زمنية.
8. في نهاية الوردية اضغط **قفل الشيفت**: يعرض النظام ملخصًا ماليًا كاملاً (محسوب تلقائيًا من قاعدة البيانات) ثم **تأكيد قفل الشيفت**. بعد الإغلاق لا يمكن تسجيل مبيعات جديدة على هذا الشيفت، ويمكن فتح شيفت جديد بعدها.

## 6. نقاط أمان مهمة

- كلمات المرور مشفّرة بـ bcrypt.
- المصادقة عبر JWT في كل طلب API.
- **الكاشير لا يستطيع أبدًا رؤية أو التأثير على بيانات فرع آخر** — يتم تحديد `branchId` من بيانات المستخدم المسجّل في قاعدة البيانات (JWT) وليس من الطلب المرسل من الواجهة، حتى لو حاول العميل التلاعب بالطلب.
- المالك (owner) فقط يمكنه إدارة المنتجات (إضافة/تعديل/حذف) والاطلاع على بيانات كل الفروع.
- أسعار المنتجات تُقرأ من قاعدة البيانات وقت البيع مباشرة (وليس مما يرسله المتصفح) لمنع التلاعب، لكنها تُخزَّن داخل الفاتورة كنسخة تاريخية بحيث لا تتأثر الفواتير القديمة إذا تغيّر السعر لاحقًا.

## 7. ملخص الـ API

```
POST   /api/auth/login
GET    /api/auth/me

GET    /api/branches

GET    /api/categories
POST   /api/categories        (owner)

GET    /api/products?categoryId=
POST   /api/products          (owner)
PUT    /api/products/:id      (owner)
DELETE /api/products/:id      (owner)

POST   /api/sales
GET    /api/sales?date=&paymentMethod=&shift=&branchId=(owner only)
GET    /api/sales/:id

GET    /api/reports/sales?from=&to=&branchId=(owner only)

GET    /api/shifts/current?branchId=(owner only)
POST   /api/shifts/open       body: { shiftType }
POST   /api/shifts/close      body: { shiftId }
GET    /api/shifts/:id/summary
```

## 8. ما لم يتم بناؤه (بالتصميم)

هذا النظام كاشير فقط، ولا يتضمن عن قصد: إدارة مخزون، مواد خام، موردين،
مشتريات، إنتاج، وصفات، محاسبة متقدمة، رواتب، باركود، ربط ميزان إلكتروني،
طلب أونلاين، حسابات عملاء، نقاط ولاء، أو عروض ترويجية معقدة.

---

## 9. ملاحظة حول الطباعة

الطباعة تستخدم نظام طباعة المتصفح (`window.print()`) على شاشة الفاتورة فقط.
تم تجهيزها لمقاس طابعة حرارية 80 مم؛ من نافذة الطباعة اختر الطابعة الحرارية
وأوقف رؤوس وتذييلات المتصفح إن ظهرت. يمكن كذلك اختيار أي طابعة A4، لكن تنسيق
الفاتورة الافتراضي مخصص للكاشير.

---

## 10. قائمة مراجعة قبل الرفع

- اضبط `NODE_ENV=production` في الخادم.
- استبدل `JWT_SECRET` بقيمة عشوائية قوية لا تقل عن 32 حرفًا ولا تشارك ملف `.env`.
- اضبط `CLIENT_URL` بعنوان الواجهة المنشورة فقط (أو أكثر من عنوان مفصول بفاصلة).
- تأكد أن مستخدم MongoDB لديه صلاحيات قاعدة `elsafeer_pos` فقط قدر الإمكان.
- لا تشغّل `npm run seed` على قاعدة الإنتاج لأنه يعيد ضبط بيانات التجربة.
